# Network engine (Go)

The network backend for the ISP billing system. PHP (Laravel + Filament) stays the
UI, CRM, billing and payment layer; this service owns everything that talks to
MikroTik hardware.

```
[ Admin / client browser ]
            |
     [ PHP + Laravel ]  ── (HTTP + shared MySQL) ──►  [ isp-engine (Go) ]
            |                                               |
     [ Payment gateways ]                        [ MikroTik RouterOS API :8728 ]
```

## What was moved out of PHP

| PHP today | Go now |
| --- | --- |
| `MikrotikController::singleWrite()` / `singleRead()` (1,000+ lines of API/SSH command building) | `internal/routeros` — native RouterOS API client, no external SDK |
| `MikrotikController::disablePPPSecret()` | `engine.suspendPPPOnRouter()` — profile redirect + session kick, hard-disable fallback |
| `MikrotikController::enablePPPSecret()` | `engine.restorePPPOnRouter()` |
| `MikrotikController::disconnectHotspotUser()` / `removeHotspotUser()` / `removeHotspotExpiryScheduler()` | `engine.expireHotspotOnRouter()` |
| `ExpireRealtimeHotspotUsers` command (every minute) | `engine.Sweep()` hotpath, same rules, real concurrency |
| `ScheduledTasksController::userDisable()` billing rules | `engine.EvaluatePPP()` — the three due-date rules, ported line for line |
| `HotspotVoucher::parseMikrotikDuration()` / `parseUptimeToSeconds()` | `internal/mikrotik` |
| Router credential decryption (`RouterList` mutators) | `internal/laravelcrypt` — Laravel `encrypt()` compatible, MAC-verified |

PHP still builds command strings for the many setup screens (firewall, queues,
VPN). Those screens are presentation-only work that does not need to move yet;
moving them is a per-screen refactor, not a rewrite.

## Why the crypto package exists

`router_lists.ip_address`, `username`, `password`, `ssh_port` and `api_port` are
stored with `encrypt()`, so the Go process must decrypt Laravel payloads:

```
base64(json{iv, value, mac, tag}) where value = AES-256-CBC(serialize(v))
mac = HMAC-SHA256(base64(iv) + base64(value), APP_KEY)
```

`internal/laravelcrypt` verifies the MAC and unserializes the PHP scalar. The
tests use payloads generated by PHP 8.2, not by Go, so interop is proven.

## Run

```bash
cd backend
cp .env.example .env      # set APP_KEY (same as Laravel), DB_*, ENGINE_TOKEN
go build ./cmd/isp-engine
./isp-engine
```

Configuration is read from the environment, then from `backend/.env` (real env
vars win). `APP_KEY` and `ENGINE_TOKEN` are required.

| Variable | Default | Purpose |
| --- | --- | --- |
| `ENGINE_HTTP_ADDR` | `127.0.0.1:8080` | Keep it on loopback; PHP calls it locally |
| `ENGINE_TOKEN` | — | Required. Bearer token for the control API |
| `ENGINE_SWEEP_INTERVAL` | `60s` | Expiry loop interval |
| `ENGINE_ROUTER_TIMEOUT` | `5s` | One RouterOS exchange |
| `ENGINE_CONCURRENCY` | `8` | Routers processed in parallel |
| `ENGINE_EXPIRED_PROFILE` | from `main_site_data` | Walled-garden profile for soft suspension |
| `ENGINE_PPP_AUTODISABLE` | `false` | Billing-driven PPP suspension (see below) |
| `ENGINE_RUN_ON_START` | `true` | Sweep once at boot |
| `ENGINE_LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` |

## Control API

All `/api/v1/*` routes need `Authorization: Bearer $ENGINE_TOKEN` (or
`X-Engine-Token`). They never return credentials.

| Method | Path | Body |
| --- | --- | --- |
| `GET` | `/healthz` | — (open) |
| `GET` | `/readyz` | — (open, pings MySQL) |
| `POST` | `/api/v1/sweep` | `{}` → summary |
| `POST` | `/api/v1/ppp/suspend` | `{"router":"core","username":"ppp1"}` → `mode: soft\|fallback` |
| `POST` | `/api/v1/ppp/restore` | `{"router","username"}` |
| `POST` | `/api/v1/ppp/disconnect` | `{"router","username"}` |
| `POST` | `/api/v1/hotspot/expire` | `{"router","username"}` (removes user + session + scheduler, deletes row) |
| `POST` | `/api/v1/hotspot/disconnect` | `{"router","username"}` |
| `GET` | `/api/v1/routers` | — |

## PHP integration

`config/network-engine.php` + `app/Services/NetworkEngineClient.php`.
With `NETWORK_ENGINE_ENABLED=true`, the `app:expire-realtime-hotspot-users`
command delegates to `POST /api/v1/sweep` and only falls back to the old PHP
sweep if the engine is unreachable.

### Enabling the PPP billing sweep

`ENGINE_PPP_AUTODISABLE` is **off by default** because the PHP schedule still
runs `userDisable()` daily at 08:30. Before turning it on:

1. Set `NETWORK_ENGINE_ENABLED=true` and confirm voucher expiry works.
2. Remove or comment out the `user-disable` entry in `routes/console.php`.
3. Set `ENGINE_PPP_AUTODISABLE=true`, restart the engine, and watch the
   `notification_logs` table plus the engine log.

The engine's customer update is conditional on `status='active'`, so even if both
sweeps overlap, `disable_count` cannot be incremented twice.

## Behaviour notes

- Vouchers: `first_login_at + validity_duration` (RouterOS units) is the expiry.
  Expired users are removed from the router and the row is deleted, exactly like
  the PHP command.
- Suspension: move the PPP secret to the expired profile, kick the session, then
  `disabled=no` so the customer can reach the walled garden. If the profile is
  missing, the secret is hard-disabled instead.
- Connections are pooled per router and re-dialed once on a transport error.
  Traps are never retried.
- `hotspot_vouchers` and `customers_infos`/`p_p_p_secrets` writes use the same
  columns Laravel uses; the admin UI keeps working unchanged.

## Tests

```bash
go test ./...
```

Coverage focuses on the parts that must not regress: Laravel crypto interop,
RouterOS framing (exact bytes per length class), duration parsing, billing rules,
and full sweeps against a fake RouterOS server.

## Known limitations

- RouterOS API only (port 8728). SSH-based commands (`/export` backups, PTY
  commands) still live in PHP. Use `api-ssl` (8729) + TLS support before
  exposing API traffic across an untrusted network, or keep it on a VPN.
- No RADIUS server yet. Hotspot/PPP service still comes from the routers; the
  `radcheck`/`radreply` tables do not exist in this schema.
- The router commands themselves are still CLI strings for the setup screens,
  which remain in PHP.
